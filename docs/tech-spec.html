1. Overview

Tasks PWA is a personal task manager that stores all data in the user's own Google Sheets spreadsheet. The app is built as a Progressive Web App (PWA) with full offline support: every write is persisted locally in IndexedDB (via Dexie) and queued for sync. When the device is online the queue is flushed to Google Sheets; on the next open the latest state is pulled back from Sheets.

Key design decisions

  • Google Sheets as the database. There is no proprietary backend. All task, folder, and label data lives in a single db_tasks spreadsheet in the user's own Google Drive.
  • Offline-first. Every mutation writes to Dexie first, then enqueues a Sheets operation. The UI reads only from in-memory Zustand state. There is no blocking network call on any user action.
  • Last-write-wins conflict resolution. When pulling from Sheets, updated_at timestamps are compared per entity; the newer record wins.
  • Calendar integration is opt-in. Google Calendar events require additional OAuth scope (https://www.googleapis.com/auth/calendar) and are enabled per user in Settings.
  • No router. Views are switched by a Zustand uiStore (SelectedView union type). The URL never changes.
  • Token persistence in localStorage. The GIS OAuth2 token is stored in localStorage (key auth-storage) to avoid prompting on every page load.
This spec covers only facts confirmed by reading the actual source code.

3. Architecture

Pattern

Offline-first PWA with Google Sheets as remote storage.

Browser
  │
  ├── React UI (components + Zustand stores)
  │     reads from: in-memory Zustand state
  │     writes via: store actions → Dexie + offlineQueue
  │
  ├── Dexie / IndexedDB  (persistent local cache)
  │
  ├── Offline Queue (Dexie `queue` table)
  │     flushed by syncService.flush()
  │
  └── Google APIs (online only)
        ├── Sheets API v4   — tasks / folders / labels CRUD
        ├── Calendar API v3 — events read + write
        └── Drive API v3    — spreadsheet search

Data-flow diagram

User action
    │
    ▼
Zustand store action
    │── 1. db.tasks.put(task)         ← Dexie write (immediate)
    │── 2. enqueue('task','update',…)  ← queue table
    │── 3. set({ tasks: [...] })       ← in-memory update
    └── 4. scheduleFlush() (800 ms debounce)
                │
                ▼
           syncService.flush()
                │── dedup by (entityType, entityId, operationType)
                │── Sheets API write (append/update row)
                └── invalidateRowCache()

Pull (on load / online / every 5 min visibility):
    Sheets API GET → upsertMany() → Dexie bulkPut → Zustand set

Write path (step-by-step)

  1. User triggers a mutation (addTask, updateTask, deleteTask, etc.).
  2. Store action builds updated entity with new updated_at = now().
  3. db.tasks.put(entity) — synchronous IndexedDB write via Dexie.
  4. enqueue('task', operationType, entityId, payload) — inserts QueueItem with status: 'pending'.
  5. set(...) — updates in-memory Zustand state; UI re-renders immediately.
  6. scheduleFlush() — 800 ms debounce timer.
  7. flush(): deduplicates queue, calls Sheets API, markDone or markFailed.
  8. invalidateRowCache() — clears entityId → row number cache.
Exception for completeTask: flushes immediately (no debounce).
Exception for recurring task completion: calls updateTask with next deadline_date from recurrenceService.getNextDueDate(), then flushes immediately. Task stays pending.

Read path

  1. AppShell mount: ensureSpreadsheet() → (if new) seedOnboarding() → initialLoad().
  2. initialLoad(): ensureHeader() on all sheets → flush() → pull() → pullCalendar().
  3. pull(): fetches tasks/folders/labels in parallel; upsertMany() on each store.
  4. upsertMany() (tasks): compare updated_at per entity; keep newer; db.tasks.bulkPut().
  5. After initialLoad(): usePrefsStore.load() reads settings!A1 JSON.
  6. useSync hook: online → fullSync(), visibilitychange → fullSync() if stale > 5 min, pagehide → flush().

Error handling

  • HTTP 401 → silent token refresh + one retry. Second 401 throws.
  • initialLoad errors: sets syncError, falls back to loadFromDb() for all stores.
  • Calendar sync errors: fall back to calStore.loadFromDb().
  • Queue items failing with retryCount >= 5 are excluded from getPending().
  • Settings save failures are silently ignored.

7. Authentication & First-Launch Setup

Full auth flow (numbered steps)

  1. App.tsx mounts; calls initAuth() from authService.ts.
  2. initAuth() dynamically injects the GIS script (https://accounts.google.com/gsi/client) if not already present.
  3. google.accounts.oauth2.initTokenClient is called with client_id, scopes (email, profile, spreadsheets, drive.metadata.readonly, calendar), and a callback that stores the token and fetches user profile from https://www.googleapis.com/oauth2/v3/userinfo.
  4. If accessToken is in authStore and not expired (> 60 s remaining): use as-is.
  5. If token is expired but user is known: call refreshToken() with prompt: '' (silent refresh — no popup if previously authorized).
  6. If neither: isAuthenticated stays false; LoginPage is rendered.
  7. On LoginPage, "Sign in with Google" calls refreshToken() which opens the GIS consent popup.
  8. After successful token receipt: isAuthenticated = true; AppShell is rendered.

First-launch setup (AppShell mount)

  1. ensureSpreadsheet():
    • If spreadsheetId is in authStore (localStorage): return { isNew: false }.
    • Otherwise: search Drive for name='db_tasks' and mimeType='application/vnd.google-apps.spreadsheet' and trashed=false.
    • If found: setSpreadsheet(id, name) → return { isNew: false }.
    • If not found: create new spreadsheet with four sheets (tasks, folders, labels, settings) → return { isNew: true }.
  2. If isNew === true: call seedOnboarding() (see below).
  3. initialLoad(): ensureHeader() → flush() → pull() → pullCalendar().
  4. ensureInbox() — guarantees the Inbox folder exists.
  5. usePrefsStore.load() — reads settings!A1 and restores sidebar states and calendar preferences.

Logout

The "Sign out" action calls handleSignOut() in Header.tsx:

  1. flush() — pushes all pending queue items to Sheets (best-effort; network errors are swallowed).
  2. clearLocalData() — clears all Dexie tables (tasks, folders, labels, queue, calendarEvents) and resets in-memory Zustand state for tasksStore, foldersStore, labelsStore, calendarStore.
  3. logout() (authStore) — revokes the GIS token, clears accessToken, user, spreadsheetId from state and localStorage.
This ensures no data from one Google account leaks into a subsequent login from a different account.

Token refresh in flight

sheetsClient.ts and calendarApi.ts both implement automatic token refresh: HTTP 401 → one refresh attempt → retry. A second 401 throws an error.

Onboarding seed data

seedOnboarding() is called once when a brand-new db_tasks spreadsheet is created. It writes all data via a single values:batchUpdate with valueInputOption: 'RAW'.

8. Synchronization / API Layer

Push path (flush) — step-by-step

  1. flush() calls getPending(): returns all QueueItem rows where status IN ('pending','failed') AND retryCount < 5, sorted by createdAt ascending.
  2. Deduplication: build Map<key, item> where key = "${entityType}:${entityId}:${operationType}". Keep only the item with latest createdAt per key. Superseded items are markDone without calling Sheets.
  3. For each surviving item: markProcessing → processQueueItem (Sheets API) → markDone or markFailed(retryCount+1).
  4. invalidateRowCache() clears entityId → sheet row cache.
  5. Update syncStore.pendingCount.

processQueueItem routing

entityType / operationTypeSheets API call
task / createappendTask
task / updateupdateTask (falls back to append if row not found)
task / deleteupdateTask with status: 'deleted'
folder / createappendFolder
folder / updateupdateFolder
label / createappendLabel
label / updateupdateLabel
Debounced flush: scheduleFlush() sets an 800 ms debounce timer. Rapid mutations (e.g. drag-and-drop reorder) are batched into a single flush.

Pull path

pull() fetches all tasks, folders, labels in parallel (Promise.all). For tasks: upsertMany() compares updated_at per entity and keeps the newer; bulkPut. For folders/labels: bulkPut all incoming records (Sheets is the authority after a pull).

Calendar sync

  1. Guard: returns if calendarEnabled === false.
  2. Fetch calendar list from GET /users/me/calendarList.
  3. For each enabledCalendarId: listEvents(id, name, color, timeMin, timeMax) where timeMin = startOfDay(today) and timeMax = today + 366 days.
  4. listEvents handles pagination via nextPageToken. Cancelled events (status === 'cancelled') are filtered out.
  5. calendarStore.setEvents(): clears Dexie calendarEvents, bulk-inserts new events, updates Zustand.
  6. On error: calStore.loadFromDb().

fullSync

Guards against concurrent calls via isSyncing. Sequence: flush() → pull() → pullCalendar(). On error: sets syncError. Always clears isSyncing.

Offline behavior

  • window.offline → isOnline = false; all writes still succeed locally.
  • SyncStatusBanner shows offline + pending count.
  • window.online → fullSync() runs automatically.
  • pagehide → flush() ensures writes are sent before the user closes/backgrounds the app.
  • visibilitychange to visible → fullSync() if last sync > 5 min ago.

9. UI Screens

AppShell layout

Renders: Header (h-14) · desktop sidebar (hidden md:flex w-60) · mobile sidebar (Radix Sheet drawer, side=left, w-60) · main content (TaskList, SettingsPage, HelpPage, or FeedbackPage). When any overlay flag is true, sidebar and TaskList are hidden.

UpcomingView

  • Data: useUpcomingGroupsWithEvents() — pending tasks with deadline + calendar events, merged and grouped by day.
  • Filters: priorityFilter, labelFilter, folderFilter, calendarFilter (multi-select, via filterMatrix).
  • Sort per group: timed items first; all-day/timeless use sentinel '99:99'.
  • Layout: WeekStrip + FilterBar + scrollable day groups. Overdue group first (red header).
  • Empty state: FolderOpen size=40 opacity-20 · "No upcoming tasks" · "+ Add task" button.
  • Special: IntersectionObserver highlights active day in WeekStrip; clicking a day scrolls to it.

AllTasksView

  • Data: useAllTasks() + calendar events (today to +366 days when enabled).
  • Sort: priority (urgent=0, important=1, normal=2) → date+time → tasks with no deadline last. Events rank as priority 2.
  • Layout: flat list, showDate={true} on CalendarEventItem.
  • Empty state: FolderOpen size=40 opacity-20 · "No tasks" · "+ Add task".

FolderView

  • Data: useFilteredRootTasks() — pending root tasks for selectedFolderId. Inbox includes tasks with folder_id === ''.
  • Sort: sort_order ascending.
  • Layout: DndContext + SortableContext. Drag right (delta.x > 50 px) re-parents task.
  • Empty state: FolderOpen size=40 opacity-20 · "No tasks" · "+ Add task".

LabelView

  • Data: useLabelTasks() — pending tasks whose labels includes selectedLabelId, sorted by priority → deadline → created_at.
  • Layout: flat list; hideLabels={true} on TaskItem.
  • Empty state: FolderOpen size=40 opacity-20 · "No tasks" · "+ Add task".

PriorityView

  • Data: usePriorityTasks() — pending tasks with priority === selectedPriority, sorted by deadline → created_at.
  • Layout: flat list; no filter bar; hideChildren={true}.
  • Empty state: FolderOpen size=40 opacity-20 · "No tasks" · "+ Add task".

CompletedView

  • Data: useCompletedTasks() — tasks with status === 'completed', sorted by completed_at / updated_at descending.
  • Layout: custom row: strikethrough title, completion datetime, label names, folder name. RotateCcw (restore) and Trash2 (hard delete) buttons.
  • Empty state: FolderOpen size=40 opacity-20 · "No completed tasks".

CalendarEventListView

  • Data: useCalendarEvents(selectedCalendarId) — events sorted by startDate → startTime.
  • Guard: if calendarEnabled === false, shows prompt to enable in Settings.
  • Layout: grouped by day; CalendarEventItem with showDate={false}.
  • Empty state: CalendarDays size=40 opacity-20 · "No events".

LoginPage

Shows ListTodo icon + title "Tasks", tagline, and "Sign in with Google" button. Button triggers refreshToken(). Shows loading state while signing in.

SettingsPage

Cards rendered in order (no section header labels):

  • Spreadsheet: shows current spreadsheet name/ID. "Change" opens an inline list of all Google Sheets from Drive (listUserSheets()). Selecting a sheet clears Dexie + invalidates row cache + runs initialLoad().
  • Priorities: toggle for prioritiesEnabled. Subtitle: "Mark tasks as Urgent, Important, or Normal". No list — just the toggle row.
  • Labels: toggle for labelsEnabled + "+" button (when enabled). List of all labels with colored dot, name, Edit and Delete buttons. Edit → ItemFormModal. Delete → ConfirmDialog → stripLabelFromTasks + deleteLabel.
  • Folders: toggle for foldersEnabled + "+" button (when enabled). Inbox shown first (read-only), then other folders sorted by sort_order. Edit/Delete per folder. Delete → ConfirmDialog → moveTasksToFolder(id, INBOX) + deleteFolder.
  • Calendars: toggle for calendarEnabled. When enabled, fetches listCalendars() and shows checkboxes. Refresh button (inline with toggle). 403 → "Grant access" → refreshToken(). Toggling a calendar → setEnabledCalendarIds() + pullCalendar().

HelpPage

Static content page. Sections: Getting started, Tasks, Views, Calendar & events, Sync & offline, Install as app. Header title: "Short guide". Uses internal Card, Para, List, Note, FeatureTable, SectionLabel components defined inline.

FeedbackPage

Requires VITE_FEEDBACK_URL. If not set, shows "Feedback is not configured yet." Text area + Send button POSTs app=Tasks&email=<email>&message=<text> with mode: 'no-cors'. Result shown via Toast.

Recurring task advancement (recurrenceService)

function getNextDueDate(task):
  if not task.is_recurring or not task.deadline_date: return null
  base = parseISO(task.deadline_date)
  switch task.recur_type:
    'days'   → next = addDays(base, task.recur_value)
    'weeks'  → next = addWeeks(base, task.recur_value)
    'months' → next = addMonths(base, task.recur_value)
    'years'  → next = addYears(base, task.recur_value)
    default  → return null
  return format(next, 'yyyy-MM-dd')

// Called in TaskItem when task.is_recurring && task.deadline_date:
nextDate = getNextDueDate(task)
if nextDate:
  updateTask(task.id, { deadline_date: nextDate })
  flush()   // immediate, not debounced
// Task stays pending with advanced deadline.

RRULE building (rrule.ts — buildRRule)

function buildRRule(opts):
  parts = ["FREQ=" + opts.freq]
  if opts.interval > 1:
    parts.push("INTERVAL=" + opts.interval)
  if opts.freq == 'WEEKLY' and opts.byDay.length > 0:
    parts.push("BYDAY=" + opts.byDay.join(','))
  if opts.freq == 'MONTHLY' and opts.monthlyByDay and opts.monthlyByDay != 'BY_MONTH_DAY':
    parts.push("BYDAY=" + opts.monthlyByDay)
  if opts.ends == 'ON_DATE' and opts.endDate:
    until = opts.endDate.replace(/-/g,'') + 'T000000Z'
    parts.push("UNTIL=" + until)
  else if opts.ends == 'AFTER_COUNT' and opts.afterCount:
    parts.push("COUNT=" + opts.afterCount)
  return "RRULE:" + parts.join(';')

// Example: "RRULE:FREQ=WEEKLY;INTERVAL=2;BYDAY=MO,WE"

Offline queue deduplication (syncService.flush)

function flush():
  items = getPending()  // status IN ('pending','failed'), retryCount < 5, sorted by createdAt
  if items.length == 0: return

  latestMap = Map()
  for item in items:
    key = item.entityType + ':' + item.entityId + ':' + item.operationType
    existing = latestMap.get(key)
    if not existing or item.createdAt > existing.createdAt:
      latestMap.set(key, item)

  latestIds = Set(latestMap.values().map(i => i.localId))

  for item in items:
    if item.localId not in latestIds:
      markDone(item.localId)   // discard superseded

  for item in latestMap.values():
    markProcessing(item.localId)
    try:
      processQueueItem(item)
      markDone(item.localId)
    catch err:
      markFailed(item.localId, item.retryCount + 1)

  invalidateRowCache()
  syncStore.setPendingCount(getQueueLength())

Mixed task+event sort (AllTasksView)

// task: sortDate = deadline_date || '9999-12-31'
//        sortTime = deadline_time || '99:99'
//        sortPriority = {urgent:0, important:1, normal:2}[priority]
// event: sortDate = startDate
//         sortTime = isAllDay ? '99:99' : startTime
//         sortPriority = 2

sort(a, b):
  aNoDate = isTask(a) and no deadline_date
  bNoDate = isTask(b) and no deadline_date
  if aNoDate and bNoDate: return a.sortPriority - b.sortPriority
  if aNoDate: return +1    // tasks without dates always last
  if bNoDate: return -1
  if a.sortPriority != b.sortPriority: return a.sortPriority - b.sortPriority
  dc = a.sortDate.localeCompare(b.sortDate)
  if dc != 0: return dc
  return a.sortTime.localeCompare(b.sortTime)

Smart title parsing (smartTitle.ts — parseSmartTitle)

Accepts an optional flags object ({ foldersEnabled?, labelsEnabled?, prioritiesEnabled? }, all default true). Each token group is skipped when the corresponding flag is false.

function parseSmartTitle(raw, folders, labels, currentFolderId, currentLabelIds, currentPriority,
                         flags = { foldersEnabled: true, labelsEnabled: true, prioritiesEnabled: true }):
  title = raw
  folderId = currentFolderId
  labelIds = new Set(currentLabelIds)
  priority = currentPriority

  // @FolderName → case-insensitive match; unmatched token stays in title
  // Skipped when flags.foldersEnabled === false
  if flags.foldersEnabled:
    title = title.replace(/@(\S+)/g, (match, name) =>
      folder = folders.find(f => f.name.toLowerCase() == name.toLowerCase())
      if folder: folderId = folder.id; return ''
      return match
    )

  // #LabelName → adds to labelIds; unmatched stays
  // Skipped when flags.labelsEnabled === false
  if flags.labelsEnabled:
    title = title.replace(/#(\S+)/g, (match, name) =>
      label = labels.find(l => l.name.toLowerCase() == name.toLowerCase())
      if label: labelIds.add(label.id); return ''
      return match
    )

  // !1 → urgent, !2 → important, !3 → normal
  // Skipped when flags.prioritiesEnabled === false
  if flags.prioritiesEnabled:
    title = title.replace(/!([123])/g, (match, digit) =>
      priority = { '1': 'urgent', '2': 'important', '3': 'normal' }[digit]
      return ''
    )

  return {
    title: title.replace(/\s{2,}/g, ' ').trim(),
    folderId,
    labelsStr: Array.from(labelIds).join(','),
    priority,
  }
